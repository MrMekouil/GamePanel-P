# CurseForge API integration

## Purpose

GamePanel needs to identify Minecraft mod files that are already installed on a server administered by the user.

The CurseForge integration is planned as a **provenance and identification source**, not as a general-purpose catalog crawler.

The primary use case is exact matching:

```text
local Minecraft JAR
        |
        v
local fingerprint
        |
        v
official CurseForge API
        |
        v
exact project/file identity when available
        |
        v
provenance shown to the server administrator
```

GamePanel should prefer an exact match over any heuristic based on a filename, display name, or guessed project.

## Expected request pattern

Requests are expected to be generated by administrator-initiated or bounded server-content scans.

The integration is intended to:

- compute fingerprints locally before contacting CurseForge;
- use exact fingerprint matching where supported by the official API;
- request only the metadata necessary to identify the matched project/file;
- make bounded requests relevant to the server content being inspected;
- stop short of broad crawling, bulk catalog replication, or HTML scraping.

If the API does not return a reliable match, GamePanel should leave the provenance unresolved rather than manufacture an identity.

## How the information is used

CurseForge results are intended to help an administrator understand the origin of locally installed content.

GamePanel may independently generate a client-content manifest from local server state. That manifest describes the administrator's content requirements; it is not intended to reproduce the CurseForge catalog or act as a binary mirror.

Handling of information obtained from the CurseForge API will be constrained by the applicable API terms. In particular, GamePanel will not persist or cache API-derived data where those terms prohibit doing so.

## Author and distribution safeguards

The integration will not treat identification of a file as permission to redistribute it.

GamePanel is intended to respect CurseForge author distribution controls and API availability. It will not:

- circumvent a disabled third-party distribution setting;
- independently rehost a CurseForge file in order to bypass platform restrictions;
- use scraping or alternate download paths to evade an API restriction;
- imply that a locally installed file is redistributable merely because it was identified.

If a file cannot be provided through an authorized route, GamePanel should preserve the distinction between identifying the content and being allowed to distribute it.

## API key handling

The API key is expected to be treated as a server-side secret.

It must not be committed to a repository or embedded in:

- browser-side code;
- generated manifests;
- exported diagnostics;
- screenshots;
- public logs.

Deployment-specific secret storage is outside the scope of this public documentation.

## Scope and load

The intended integration is small and demand-driven. It is not designed to mirror CurseForge or continuously ingest the platform.

The number of requests should remain tied to files actually being inspected by an administrator, with batching used where the official API supports it.

If future usage approaches limits defined by CurseForge, the integration will need to follow the applicable quota/licensing requirements before increasing traffic.

## Project status

GamePanel is under active development. The CurseForge integration described here is a planned integration and depends on approved API access.

This public repository exists to document the integration purpose and safeguards without publishing GamePanel's private implementation details.
